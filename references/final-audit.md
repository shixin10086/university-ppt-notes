# 全稿教学验收

本流程用于整讲逐页备稿全部完成后的最终检查。目标是发现单页自检和五页试讲难以识别的跨页、跨章节和全讲尺度问题，不是为了统一风格而重写全稿。

## 执行边界

- 以用户最后确认并写入的唯一累计稿为检查对象，旧稿和未确认草稿不得混入。
- 第一遍只检查并列出问题，不直接修改已确认内容。
- 保留自然、准确且已经通过检查的页面，只报告有可观察证据的问题。
- 对照用户确认的全讲分析报告，检查最终章节关系、详略规划、图示判断和去重策略是否落实；报告本身不是讲稿内容，不得写入PPT备注。
- 不因为偏好不同就提出改写，也不以“可以更好”为理由扩大返修范围。
- 用户确认问题清单后才集中修改。修改某页时同时复查前后各一页，但不得顺带改动无关页面。

## 第一轮：硬性校验

检查可确定的结构和字数要求：

如果累计稿为Markdown且PPT已有 `slide_extract.json`，先运行 `../scripts/audit_notes.ps1` 获取确定性结果；脚本只能发现结构和字数问题，不能代替后续三轮教学判断。

1. PPT总页数、备稿页数、页码和顺序一致，无缺页、重复页或错序。
2. 页面标题与PPT对应，章节编号、协同方式编号、案例编号和小结名称准确。
3. 封面、目录、章节过渡、普通内容、课堂思考和视频页使用正确格式。
4. 普通内容页的引入为一句且不超过60字，收束为一句且在35—45字。
5. 正文符合该页已经确定的简讲、常规、重点或核心层级；用户指定的简写页不得恢复为完整流程复述。
6. 课堂思考页明确提示学生开始思考，任务强度与PPT一致；视频页只承担播放和必要观察提示。

硬性校验问题直接标为“必须修改”，但第一遍仍只报告，不自动写回。

## 第二轮：PPT内容核对

逐页对照真实幻灯片的文字与渲染图：

1. 备稿是否遗漏影响本页结论的对象、条件、关系或限制。
2. 是否添加PPT未支持的事实、数值、因果、技术能力或案例过程。
3. 专业概念经过口语化后是否仍然准确，有没有因简化而扩大或缩小原意。
4. 是否把编号、箭头、卡片或并列排版误认成流程图、原理图或示意图。
5. 真正承担知识的流程图、原理图和示意图是否讲清对象关系及其支持的结论。
6. 是否不必要地描述普通照片、装饰图、设备图和效果图。

## 第三轮：教学合理性检查

这一轮先判断内容是不是合理的教学备稿，不先追求语言顺滑。既检查单页有没有完成教学任务，也把全部页面看作一堂完整课程，而不是若干独立段落：

1. 整讲是否形成清楚的教学主线，各节进入、展开和小结是否各自承担明确作用。
2. 相邻页面从上一主题转入下一主题的依据是否清楚，有无突然跳转或提前讲完后页内容。
3. 上一页收束与下一页引入是否连续重复同一结论。
4. 同一概念、流程或协同方式是否在不同案例中反复详细讲述。
5. 首次出现的基础概念和核心机制是否讲透；后续案例是否把篇幅放在新增约束、组织差异和特色结论上。
6. 重点页是否有足够解释，辅助页、操作页和重复流程页是否适当略讲。
7. 小结页是否综合出判断、选择依据或知识关系，而不是简单压缩罗列前文。
8. 每页是否帮助学生理解“为什么、怎样关联或会产生什么结果”，而不是只说明PPT列出了什么。

只有这一轮通过，才能进入连贯性检查。教学内容、知识顺序或详略尚不合理时，不得用连接词和语言润色掩盖问题。

## 第四轮：连贯性试讲与Humanize检查

代入大学教师连续试讲，检查已经合理的教学内容能否自然讲出来，再用Humanize处理确有证据的生硬表达；不能只做词语替换或表面口语化。

连续朗读并检查真实课堂表达：

1. 语言是否像大学教师在解释知识，保持专业但不书面僵硬，也不变成日常聊天。
2. 是否存在PPT摘要、材料总结、页面导航或“这张图展示了”等由版面支配讲述的表达。
3. 是否存在连续短句、压缩分句、成串名词或逗号前后关系生硬的问题。
4. 因果、条件、转折、顺序和递进是否清楚；连接词是否真正有用，是否机械重复“因此、同时、此外”等词。
5. 是否反复使用“核心是”“可以分为”“首先、其次、最后”等统一模板，或连续多页采用相同句式和讲解结构。
6. 是否存在设问、自问自答、空泛课堂话术、AI式二元对立、刻意总结或过分规整的标准答案表达。
7. Humanize是否保留专业结论、条件和边界，没有为了自然表达而损失准确性。
8. 引入、正文和收束连起来是否能直接讲出口；相邻页连续朗读是否出现重复、停顿异常或语义断裂。
9. 单页讲述是否形成“提出本页重点—解释关键关系—落到本页认识”的自然推进，而不是把PPT要点拼接成一段总结。
10. 逗号、分号和句号前后的内容是否存在真实的语义承接；即使每句话单独正确，只要连续讲述显得硬接、突转或过度规整，也应标为教师口吻问题。
11. 教师是否掌握讲述主动权：需要借助图示时，用图来解释知识关系；不需要时，直接讲知识，不按版面顺序逐项报读。
12. 逐项对照 [质量基准示例](quality-benchmarks.md) 中全部已审核错误示例，检查是否出现相同错误机制。对照对象是专业失真、关系断裂、聊天化、导航化、收束越界等机制，不是原句关键词。

## 问题分级

- **必须修改**：事实或专业含义错误、与PPT不符、漏掉核心知识、格式或字数违反硬规则、页间逻辑断裂、误判关键图示。
- **建议修改**：重复明显、详略失衡、表达像PPT摘要、Humanize不足、衔接生硬，已经影响课堂理解或听感。
- **可以保留**：存在个人表达偏好差异，但含义准确、讲述自然，不影响整讲逻辑。

不得把“可以保留”包装成待修改问题。若全页通过，不必为该页制造意见。

## 首次验收输出

先给出总体结论，再按页码列出问题。每项使用以下字段：

- 页码与标题
- 严重程度：必须修改 / 建议修改
- 问题类型：硬性格式 / PPT对应 / 专业准确 / 页间逻辑 / 详略重复 / 图示处理 / 教师口吻
- 证据：引用足以定位问题的原句或说明具体页面关系
- 修改方向：说明应修正什么，不在本阶段提供整页改写

最后汇总：必须修改页数、建议修改页数、主要共性问题，以及不需要修改的页码范围。问题较多时分章节提交，不能因为篇幅限制省略后半部分。

## 返修与复验

1. 用户确认问题清单后，只修改确认的问题页，并完整列出修改后的引入、正文和收束供审阅。
2. 修改页必须重新检查字数、PPT依据、专业含义和Humanize结果。
3. 连续朗读修改页及其前后各一页，确认没有产生新的重复或跳转。
4. 全部返修确认并写回后，再运行一次硬性校验，并对各章节连接处、小结页和全讲收尾进行复验。
5. 页码连续、格式字数合格、没有未处理的“必须修改”问题，且连续试讲无明显断裂时，才报告全稿验收通过。
