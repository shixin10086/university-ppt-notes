# 伙伴Skill分工与调用顺序

本Skill是总控层，在同一任务中组合调用 `ppt-speech-writer`、`humanize` 与 `teacher-oral-delivery`。只有证据、教学组织、去AI写作和教师口述四层分别完成职责，才算执行了完整流程。

## 一、固定分工

### `ppt-speech-writer`：PPT证据层

只使用以下能力：

- 提取文本框、表格、图表、图片、备注和OOXML文本
- 渲染全部幻灯片
- 对复杂页执行OCR或视觉检查
- 建立逐页可见元素清单
- 将最终确认稿写入PPT备注栏

不要执行它自己的语言确认、演讲时长预算、叙事弧确认、逐页显示稿、术语表、暂停标记、强调标记和Transition格式。它不能直接决定本项目的讲稿结构。

### `university-ppt-notes`：教学组织层

负责：

- 只依据PPT证据和用户当前对话指令确定内容
- 建立整讲主线、15页上下文窗口和跨案例去重
- 判断页面类型、详略、图示讲法和页间逻辑
- 按本Skill规定生成引入、备稿、收束及特殊页面模块
- 每5页送审、确认后写入累计稿
- 执行教师试讲和全稿验收

### `humanize`：表达重写层

在全讲分析已经确认、当前页面事实卡完成后使用，重点处理：

- 重新安排信息进入顺序，而不是只替换词语
- 合并提纲式短句，修正逗号、分号和句号之间的生硬连接
- 根据真实语义使用因果、转折、条件和承接词
- 消除PPT摘要、机械罗列、统一模板和报告式语言
- 保留必要专业词、条件、边界和结论

`humanize` 的“最小有效修改”只适用于用户已经确认的页面；新生成页面不提供完整书面初稿，而是根据非文章式事实卡直接完成第一次课堂成文。它不能把教师语言改成聊天口吻，也不能改变格式和字数规则。

新稿不得直接采用通用 `humanize` 的最小修改默认值。必须执行 [大学讲稿强Humanize协议](humanize-protocol.md)：先建立非文章式事实卡并直接成文，再执行一次只检测不改写的检查；出现事实卡序列化、报告模板或五页结构重复时，回到事实卡重新生成整页。

### `teacher-oral-delivery`：教师口述层

在Humanize通过后执行，负责：

- 按照学生一次听懂的顺序调整段内信息，让对象、条件、变化、依据和结论自然展开；
- 把已经准确、去AI化的文字稿改成教师可以连续讲出口的句子；
- 检查每个分句之间的真实语义关系、主体、动作和对象是否清楚；
- 根据相邻页面修复朗读时的突然换题、重复铺垫和生硬承接；
- 保留专业事实、页面重点、格式、详略和字数限制；
- 删除无教学功能的口头禅、设问、聊天化措辞和PPT导航话术。

默认采用“中度语言改动＋较强解释逻辑”，不是完全重写。口述层不能用“大家注意”“对吧”“是不是”“其实”“那么”“我们来看一下”等填充语制造教师感。完整规则见 [teacher-oral-delivery](../companion-skills/teacher-oral-delivery/SKILL.md)。

## 二、固定调用顺序

1. `ppt-speech-writer` 完成PPT提取、渲染与视觉证据整理。
2. 本Skill把全讲教学主线、页面组逻辑、视觉清单、详略和去重规划完整呈现给用户；用户确认前不生成首批讲稿。
3. 用户确认全讲分析后，本Skill根据整讲和前后页关系建立非文章式事实卡，不生成完整书面初稿。
4. `humanize` 根据事实卡直接完成第一次课堂成文，并用检测模式执行第二遍检查；失败稿回到事实卡重新生成，确认稿仅做最小必要修改。
5. `teacher-oral-delivery` 对Humanize结果执行口述转换，并用正常课堂语速连续朗读当前5页；它只改变表达，不改变内容。
6. 本Skill以大学教师身份连续试讲，检查准确性、详略、连贯性、口述结果和格式。
7. 用户审核当前5页；确认后写入累计稿。
8. 全部页面完成并通过终检后，再使用 `ppt-speech-writer` 的备注写入能力，或使用本仓库的导出脚本完成交付。

不得把顺序改成“先由 `ppt-speech-writer` 或本Skill写完整书面讲稿，再交给 `humanize` 润色”，否则早期句序会锚定最终表达，其时长、转场和逐元素覆盖逻辑也会干扰本Skill的详略与讲稿结构。

## 三、缺失处理

- 开始任务时检查三个伙伴Skill是否已经可用；仓库内置的教师口述层可以由主Skill直接读取执行，也可以单独安装后调用。
- 缺少任一个时，准确说明缺少哪一个，并询问用户是否安装；不要声称已经使用。
- 用户明确不安装时，可以继续使用本Skill已有规则完成降级版本，但必须说明缺少的能力：没有 `ppt-speech-writer` 时无法保证完整视觉取证，没有 `humanize` 时只能由本Skill自身规则进行去AI检查，没有教师口述层时无法保证独立的逐句朗读转换。
- 是否安装、从何处安装以及安装产生的外部变化，必须遵循当前环境的授权流程。
