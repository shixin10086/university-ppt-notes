# 课堂成文与Humanize复核

本协议只在当前5页已经分别完成独立初稿后加载，把“写成教师讲稿”和“检查AI式表达”分开。第一版讲稿由 `university-ppt-notes` 根据PPT事实、页面教学任务、前后页关系和一个对应优质样稿直接生成；`humanize` 只在成文后使用检测模式，不负责确定页面重点或自由重写。

## 一、直接成文输入

每页只准备完成写作所需的信息：

- PPT中能够确认的事实、术语、对象关系和图示证据；
- 学生听完本页后应理解的一个核心认识；
- 当前页与前后页面的分工，哪些内容已经讲过，哪些留给后文；
- 页面类型、详略层级、字数和不得改变的专业边界；
- [首次成文核心流程](drafting-core.md) 所路由的一个独立样稿。

这些信息只用于决策，不套入固定表格，也不按照列出顺序拼成段落。

## 二、先判断教学任务，再成文

在五类主要教学任务中选择最接近的一类：

1. **知识或概念页**：从学生需要理解的对象进入，说明必要的现象、原因和概念边界。
2. **原理图、流程图或示意图页**：抓住图中真正承载知识的关系、变化或机制，不逐项报读版面。
3. **案例或场景页**：承接已经讲过的共性，把篇幅用于本案例新增的条件、判断和结果。
4. **目录或章节过渡页**：交代清楚学习路径或当前章节任务，不写成报告目录，也不提前讲完正文。
5. **小结页**：把本节知识重新连接成判断方法或因果链，不只重复标题和名称。

页面可能兼具多种特征，但只选择一个主要教学任务作为成文入口。示例只提供讲述方式，不提供可复制的内容、句式或固定结构。

第一版直接写成教师可以讲出口的语言。口语感来自信息顺序清楚、句间关系自然和解释充分，不来自设问、口头禅、俚语或降低专业精度。

## 三、Humanize只做检测

把5页组合并连续读完后，以 `humanize` 的Detect模式查找有明确文本证据的问题，重点包括：

- 把PPT结构、页面标题或条目换一种说法重新念一遍；
- 连续使用相同开头、并列框架或总结句式；
- 短句堆叠、搭配生硬、主体跳跃或分句关系不清；
- 为了口语化加入聊天措辞、空话或改变专业含义；
- 同页或跨页重复已经讲清的内容。

检测只报告实际出现的问题，不评分，不猜测作者，也不把所有句子都列为待修改对象。

## 四、修改边界

- 局部措辞、衔接或重复问题，由本Skill做最小必要修改。
- 页面重点、专业边界或整体信息顺序判断错误时，由本Skill重新依据PPT和对应样稿成文。
- `humanize` 的建议与PPT事实、用户确认内容或当前课程风格冲突时，不采用该建议。
- 已经准确、自然、具有教学作用的句子没有问题就保留，不为显示执行了Humanize而修改。
- 修改后只再检查受影响的句子和必要的相邻页面，避免循环润色。

## 五、完成标准

1. 本页知识由教师的解释逻辑组织，而不是跟随PPT版面。
2. 学生听完能够说出本页的核心认识及必要依据。
3. 五页的讲述方式随教学任务变化，没有统一模板。
4. 专业事实、条件、边界和结论与PPT一致。
5. Humanize只修复有证据的问题，没有破坏原本自然的表达。
